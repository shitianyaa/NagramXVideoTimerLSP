# Agent Note: 听视频与会话共享队列

Status: implemented

## Problem

定时播放已能把视频交给宿主继续播放。独立的听视频页需要在同一个播放会话里提供拖进度、换条和回到画面，并能够访问同一聊天的共享视频。Niagram 1322 内联了旧的 MediaController 转交方法，已有 1276 映射无法覆盖。

## Decision

听视频页使用宿主的 BottomSheet、ActionBar、倍速菜单、进度条和播放图形。视频菜单和对应的迷你播放器都打开同一面板，入场和退出采用宿主的短距离右滑淡入淡出，具体取舍见[听视频过渡与进场工作量](2026-11-25-listen-video-transition.md)。定时和队列各有一个入口，面板色彩取当前宿主主题。听视频窗口将背景绘制到系统栏，内容通过窗口安全区避让。

面板挂载后在下一帧请求关闭原画面，宿主入场动画完成后再加载共享视频。返回画面时，宿主接管播放器并恢复进度和暂停状态后，听视频面板才退出。NagramX 使用宿主的原生后台接口，Niagram 1322 使用 PhotoViewer 保留的转交方法。Niagram 1322 的聊天滚动入口 `Lq()` 和 `er(boolean, boolean)` 进入后台播放保护。保护作用域随滚动调用退出，手动停止仍可结束会话与定时。

共享视频从宿主的媒体接口按当前账号、对话及话题分页加载，消息 ID 在对话内负责去重和排序。列表在同一面板内追加结果，并用首个可见条目恢复滚动位置。定时状态从当前宿主的播放会话读取。

播放列表设置完整的滚动高度，只创建和复用可见范围及上下缓冲区内的行。文件状态在工作线程查询，结果只写回仍绑定同一条消息的行。主封面保留宿主的缩略图视图，跟随宿主显示动画设置切换，并低优先级预取相邻视频的缩略图。

迷你播放器的倍速按钮在后台视频会话中使用宿主的非音乐倍速，与详情页共用读写路径。宿主的音乐样式只在倍速回调期间切换，回调结束后恢复。音频消息沿用宿主原来的倍速路径。

Niagram 1322 的迷你栏文案控件使用 `f(CharSequence, boolean)` 写入标题和倒计时。渲染在主线程读取当前播放项，只给已绑定同一条视频的音频栏设置两行布局。标题沿用通知的说明首行，缺少说明时用本地化视频标签和消息编号区分。副标题预留倍速和关闭按钮的空间。

换条时，Niagram 的播放通知会同步进入聊天页的 `er(boolean, boolean)`。该方法可能把刚启动的后台视频视为离屏视频并清理。保护只拦截来自聊天页的停止服务调用，宿主换条时仍可释放旧播放器。宿主接受新条目却清空播放器时，模块恢复原条目的进度和暂停状态。方向键在本次会话内绕过启动失败的条目，列表仍可手动重试。

## Alternatives considered

直接扩展宿主 AudioPlayerAlert 能重用完整音频控件，但会把新页绑定到两个宿主的内部布局，且 Niagram 1322 已重命名该面板。新建音频播放器有独立控制权，但需要额外维护进度、缓冲和通知状态，回到原视频时也要重新同步。

最初选择底部展开，是因为听视频从正在播放的视频或迷你播放器进入，与宿主音频播放器的入口语义一致。后续对全高面板的过渡采样支持改用短距离右滑，新的取舍和验证见[听视频过渡与进场工作量](2026-11-25-listen-video-transition.md)。

宿主 RecyclerListView 提供完整的列表回收机制。Niagram 1322 的适配器类型经过混淆，当前面板沿用已验证的滚动容器，并限制同一时刻绑定的行数。

## Consequences

播放状态和媒体服务仍由宿主管理。Niagram 的类发现遵循[混淆类的结构解析](../bug-fix/2026-11-25-niagram-r8-class-discovery.md)，方法与参数顺序仍依赖已核对的 DEX 接口，升级后须复核。桌面回归覆盖队列排序、会话隔离、换条、滚动清理保护和返回画面的接管回调。窗口层级、动画连贯性及混淆调用仍需 LSPosed 设备验证。
