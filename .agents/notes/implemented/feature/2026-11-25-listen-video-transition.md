# Agent Note: 听视频过渡与进场工作量

Status: implemented

## Problem

听视频面板占满可用高度，底部展开需要移动整个屏幕。视频页进入时还会重复收集播放列表，播放器交接、窗口移除和入场动画集中在同一时段，出现明显长帧。

## Decision

听视频页通过宿主 BottomSheet 的 `transitionFromRight(true)` 使用 48dp 的横向位移与透明度过渡。当前两个宿主的入场时长为 250ms，退出为 200ms。视频菜单和迷你栏共用该设置。

视频菜单进入时，将已取得的播放列表传给 PhotoViewerAgent。原来的单参数关闭入口仍按需收集列表。播放器转交、暂停恢复、原视频窗口下一帧关闭以及动画结束后加载共享视频的顺序沿用现有实现。

历史笔记检索中，仅[听视频与会话共享队列](2026-11-21-listen-video.md)部分重叠。该篇保留会话、队列和控件的决策，本篇接管动画方向与时长的选择，两篇互链。

## Alternatives considered

原有底部展开与宿主音频播放器的入口一致，且只需复用 BottomSheet 默认动画。全高面板的纵向行程长，对照采样出现更多长帧，当前改用宿主已有的短距离横向过渡。

自定义页面动画可以独立调整时长和曲线，但需要额外维护动画状态、取消和退出行为。宿主已有公开的过渡入口，可以保留其动画生命周期与通知锁逻辑。

## Verification

Niagram 13.2.2、同一设备、同一条暂停的 54分47秒视频，每个入口各采样 5 次。每次重置 gfxinfo，点击后等待 0.72 秒取得 framestats。P95 和 P99 为每次整应用窗口统计的中位数，包含宿主和面板绘制。

| 路径 | 复用列表与底部展开 P95 / P99 | 复用列表与右滑 P95 / P99 |
| --- | --- | --- |
| 视频页进入听视频 | 69 / 150ms | 42 / 85ms |
| 听视频返回画面 | 48 / 113ms | 34 / 85ms |
| 迷你栏进入听视频 | 32 / 69ms | 16 / 57ms |

两个版本都复用预先取得的列表。该对照用于选择动画，列表复用本身的独立性能收益尚未量化。最初基线使用另一条视频，保留原始数据供排查，未并入上表。

录屏按 30fps 抽取控件区域，视频页进入时从原视频头部淡入听视频头部，未观察到聊天页闪露。暂停状态往返后媒体位置仍为 1153000ms，30分钟定时保持 30:00。桌面回归增加预先取得的完整列表、暂停和进度断言，反转列表选择条件时完整列表断言失败。

播放中连续完成 3 轮视频页和迷你栏往返，媒体状态保持 PLAYING，位置从 1153000ms 推进到 1163000ms，定时显示 29:48。验证后取消本次测试定时。构建、135 项 JVM 回归通过，Lint 为 0 错误、16 条警告。设备安装包与本地 APK 的 SHA256 一致。NagramX 的宿主方法已核对，本轮设备定量采样仅覆盖 Niagram。

临时采样、录屏和帧图位于工作区 `Temp/listen-transition/`。

## Consequences

全高页面的位移距离和动画时长缩短，继续复用宿主动画生命周期。Niagram 的进场采样仍有约 85ms 的长帧，播放器交接与窗口创建仍有优化空间。实测数据受刷新率、宿主渲染和设备负载影响，后续比较需保留相同的采样路径与视频状态。

`transitionFromRight` 依赖当前已核对的两个宿主实现，升级后需复核 DEX 方法及过渡行为。
