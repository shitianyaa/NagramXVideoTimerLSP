# Agent Note: Niagram 混淆类的结构解析

Status: implemented

## Problem

Niagram 的两个 versionCode 1322 安装包采用不同的 R8 类名。新版的 MessageObject 从 qo6 变为 oo6，FileLoader、MediaDataController、SharedConfig、PlayPauseDrawable 和 NumberPicker 也改名。宿主识别条件提前退出，其他旧短名还可能加载到无关类。

## Decision

MessageObject 和 VideoPlayer 从 PhotoViewer 保留的字段取得 Class，反射签名比较使用类型身份。其他 12 个混淆类由 DexKit 2.3.0 按多项字段、父类、方法和字符串特征查找，唯一候选才进入宿主类映射。缓存包含 APK 路径与内容的 SHA-256 指纹及解析规则版本；主 APK、拆分 APK 或规则变化后重新解析。缓存命中时仍验证类可加载及反射结构。

单项查找缺失或歧义时记录具体类和候选数，其他唯一候选仍可使用。缓存通过空值记录缺失的可选类，调用方沿用原有的空接口处理。解析结束后关闭 DexKitBridge，原生库只在需要重新查询时加载。

此变更处理类型发现及受影响的签名校验。现有播放器操作和已经核对的方法名继续使用原有能力检查；R8 方法内联和方法名变化需要另外的行为特征。原有 niagram1322 标记表示该播放器布局分支，识别使用结构条件，日志不再凭该分支填入固定版本号。

构建与测试入口统一由 Gradle 解析依赖，开发包沿用 Gradle Debug 签名，旧手工 javac/d8 和 module/mod.keystore 打包路径由薄包装脚本替代。APK 包含四种 ABI 的 libdexkit.so 和第三方许可说明。独立 JVM 测试在 module/build/test-libs 中取得编译依赖，PowerShell 和 Bash 入口均显式指定项目及测试输出目录。

被修改的视频列表类同时落实阿里规约 01-(七)4：文件检查使用单工作线程、容量 64 的有界队列与明确拒绝策略，饱和时记录日志并保留已有时长文案。HostProfile 的三处空反射异常处理按 02-(三)补齐诊断。

历史检索中，[听视频与会话共享队列](../../implemented/feature/2026-11-21-listen-video.md)与混淆接口约束部分重叠，保留其播放和队列决策，本篇接管类发现策略。[听视频过渡与进场工作量](../../implemented/feature/2026-11-25-listen-video-transition.md)涉及相邻播放路径，过渡决策保持独立。

## Alternatives considered

直接更新六个短名改动小，也能恢复当前正式包；同一版本号的另一构建仍会失配，无法减少后续的类型名维护。

全量重写播放器的方法定位可以扩大适配范围，但会同时改变已验证的播放和通知路径。本次先消除已经发生的类重命名故障，保留方法能力检查与真机验证边界。

逐个加载宿主所有类可以只用反射完成搜索，但会触发无关类的链接和反射开销。DexKit 在 DEX 元数据中筛选后只加载唯一候选，并在完成后释放原生资源。

## Verification

- 12 项生产查询在旧包 81fb24a 与正式包 127b70d 的完整 DEX 中均唯一匹配预期类；原有 11 项从生产代码导出验证，新增平台回调按父类及两个方法描述符独立核对。正式包 SHA-256 为 19ff08b5a0fce2d7d8f50525b1cfbc99107a5b6a3409f52c5eae449233f66abf，与设备安装包一致。
- 157 项 JVM 回归通过，覆盖任意类型名、同签名无关类型、缺失和歧义、部分能力保留、相同版本和文件长度及时间戳下的内容变化、拆分 APK 和规则变化、损坏缓存。反转唯一候选判断后回归失败，恢复后通过。
- 从工作区根目录调用 PowerShell、Git Bash 的测试脚本与开发构建入口通过。Debug、正式签名 Release 构建及 Lint 通过。
- 设备 LSPosed 7912 / API 102 上，DexKit 原生加载和查询成功，重启后日志命中 APK 指纹类缓存并完成 Hook 安装。已验证听视频、缩略图和本地文件状态、共享视频列表切换、定时继承与暂停冻结、系统播放/暂停、取消定时及返回暂停画面。测试定时已取消。
- 临时日志、截图、特征检查及变异实验位于工作区 Temp/niagram-r8-fix/。本轮 NagramX 仅复用原有 JVM 回归，未重做完整真机交互。

## Consequences

类型名变化可以自动解析，两个同版本构建的旧短名不会混用。DexKit 增加原生库、传递依赖及首次查询开销；缓存复用仍需读取 APK 计算指纹。宿主字段、字符串或父类改变时，需要复查对应特征。

Niagram 的原有方法级缺口仍在能力日志中报告。系统上一条／下一条入口采用[系统媒体切换复用听视频队列](2026-11-25-system-media-video-skip.md)的后续决策与验证。最新源码 a390191c 对应的开发构建未制作 APK，本轮实际安装和验证覆盖 127b70d 正式包。Debug 与正式 Release 的签名分别保留，设备使用与原测试模块同证书的 Debug 包。
