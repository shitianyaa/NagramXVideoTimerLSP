# Agent Note: 音频定时只保留时长

Status: implemented

## Problem

音频定时面板的「播完当前曲目」与宿主播放顺序菜单的「播放一次」重叠，增加选择和结束事件处理的维护成本。

## Decision

音频定时只保留按时长停止，包含预设、自定义和取消。当前曲目结束后停止由宿主「播放一次」处理。音频状态机移除结束后停止模式和相应的手动换曲取消分支，正常结束事件继续交给宿主处理。

本决定部分替代[音乐与音频文件定时关闭](../feature/2026-11-25-audio-sleep-timer.md)的独立曲目结束模式；更多菜单入口、实际播放时间、语音排除、账号隔离及视频定时保持原有契约。桌面回归中的曲目结束验证改为检查透传及按分钟计时继承。

## Alternatives considered

保留模块自己的曲目结束模式可以避免改变宿主循环设置，但同时保留两个完成相近目标的入口。选用宿主已有的播放一次，简化音频面板。

只隐藏面板行改动较小，但留下音频独有且没有入口的状态分支与文案。收窄音频 arm 接口为时长，删除对应分支和文案。

## Consequences

音频入口更集中，结束模式和测试数量减少。播放一次会采用宿主自身的播放模式语义，模块不额外维护一套保留循环设置的结束策略。视频继续使用其现有曲目结束选项。

JVM 227 项回归覆盖新契约；Debug、Release 与 Lint 作为交付检查。Niagram 13.2.2 真机检查音频面板不出现重复项目，以及小时分钟范围联动。
